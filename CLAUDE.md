# parallels

A light-context agent harness: orchestrator → worker → reviewer loop, each agent in a tmux window. See PLAN.md for the design.

Bun + TypeScript. Use `bun` for everything (`bun test`, `bun run check`, `bun src/cli.ts`). No Node, npm or vite.

Layout:

- `src/cli.ts` — `start [project] [git-url]`, `msg`, `agent`, `agent-exit` (internal: the follow-up after a non-zero agent exit), `version` commands. `start` opens the inline TUI; run inside a git repo, it opens the `orch-xxxx` project cloned from that repo's origin, creating one if none exists (`repoHere` / `projectFor` in `src/commands.ts`), and Ctrl+N clones from it too
- `src/tui/` — the bare inline TUI, like Claude Code and Codex: no alternate screen; finished lines of the active page go once into the terminal's own scrollback (scroll with the terminal; no PgUp/PgDn), and only the live region at the bottom (the partial streaming line, a menu or the project list, the status line, the input area) is redrawn; switching pages, resizing, `/agents` and `/back` clear the screen and scrollback and reprint that page (or transcript); output for a page that is not active only goes into its history; quitting drops the live region and leaves the output with the cursor on a fresh line. Frames are throttled (one per 16ms at most) and a resize reprints once it has settled (120ms; nothing is drawn meanwhile); the live region shows "opening…" while the start pages open, and nothing is cleared at start; every page opens rebuilt from its orchestrator's transcript like `claude --continue` / `codex resume` (`restore.ts`), so the first page is printed under the shell's output and later ones on switching to them; ↑/↓ input history is per project (`history.ts`); console output (e.g. the config loader's warning) is routed into the scrollback while the TUI runs; a frame that throws is reported once and the app keeps going. `app.ts` (one page per orchestrator; a page's history (`Line[]`) keeps plain lines as they are and the orchestrator's markdown as written (streamed blocks, and replies led by their sender), laid out at the current width whenever drawn, so reprints after a resize fit tables again; only orchestrator text (the stream, replies, and, in the `/agents` view, every agent's assistant text — worker and reviewer too, as Claude Code renders subagent text — via `parts` in view.ts) is markdown, while user messages, commands, errors and tool lines (written with `plain` set by agent.ts) stay plain; Ctrl+N starts `orch-xxxx` at once, `/rename <name>` sets a display name only (saved in `projects/<id>/name`; the folder, id, tmux session and running agents are untouched, so it works mid-turn; names must be unique, printable, no bidi overrides; `/new <id>` and Ctrl+N's orch-xxxx never reuse another project's display name), Ctrl+Z / Ctrl+X switch, Ctrl+B or `/projects` (Ctrl+B is tmux's prefix) toggles a list of every project, drawn like the /models menu above the status line: ↑↓/jk, Enter opens and closes it, `p` pins (config `pinned`), `d` deletes after a plain y (Ctrl/Alt chords do nothing in the list), Esc closes; rows show each project's display name (`/rename`) while open, pin, delete and live checks use its id; `AppDeps.projects` stubs its tmux checks in tests; `/keys` echoes what the terminal sends; slash commands live in one table, `App.commands` (name → `{ run(args, page), args?, needsPage?, help }`; `parseCommand` matches the name up to the first space, and a command without `args` matches only bare, so "/quit now" is unknown), and `submit` is parse → guard → run (a command that needs no page runs at once; with no page, `/agents`, unknown commands and plain text open a fresh orch-xxxx instead; plain text is refused in an agent view and queued while signing in); keys go through `App.keyLayers`, an ordered list of `{ takes(k) (pure), handle(k) }` where the first taker wins: keyEcho → chords (Ctrl+C/N/Z/X) → projects (Ctrl+B, the open list) → menu → questions (`Questions.takes`) → escape → enter → editor (`EDITS`); `/help` is built from the command table (`helpLines`, rows laid out by `HELP_LAYOUT`) and lists the commands: `/agents` picks a transcript to view live, `/back` leaves the agent view (listed only there), `/models [id]`, `/questions`, `/review-rounds [n]` (shows or saves `maxReviewRounds`; the orchestrator re-reads config every turn, so it applies from its next turn), `/accounts`, `/login claude [profile] | codex [profile]` (aliases: anthropic/openai), `/new [name] [git-url]`, `/close` closes the whole page, `/quit`. Every command works at any time: mid-turn, while viewing an agent (plain text there is refused until `/back`), and while signing in (a second `/login` is refused; plain text is held in the app and sent as soon as sign-in succeeds, or dropped with a note if it fails); a dimmed status line above the input shows the page's display name, remote and the number of open pages, led while a turn runs by a braille spinner "thinking…/working… Ns" (a live `/agents` view shows "following <agent>" instead, re-checked via tmux (`liveAgents`) about once a second, one call per project at a time), and "N busy" for busy background pages; a 100ms timer animates it only while something is busy — `AppDeps.clock` and `agents` are injectable for tests; the status text is built in app.ts, apart from the layout), `restore.ts` (pure, the transcript's current branch (`Transcript.branch()`, as the orchestrator already loaded it: `Orchestrator.entries()`, read after openOrchestrator, no second file read) → `Line[]` as the page showed them live: a summary leads with a dim "… earlier conversation summarized"; user messages as "> …" (`userLines`, also used by submit), agent messages as one dim "From <id>: <first line>…" cut at 100 code points (`reportLine`; live they come from `onInbox`, and a "user" message not typed in this TUI (`parallels msg`) shows live as "> …" too, a question's answer or skip (`questionReply`: the id, anchored to questions.ts's id shape, is looked up in questions/ so the question's own text cuts the message; a one-line regex only when the file is gone) as its dim "? <question> → <answer>" line (`answeredLine`) both live (unless answered in this page: shown when answered) and restored, while typed ones (`page.sent`) are not shown twice; within one inbox batch the user's lines go first), assistant text through a fresh `MarkdownStream` per entry (every entry ends flushed live: a tool line, the turn's end or an inbox batch ends the markdown), tool calls as the `toolLine` from view.ts that agent.ts writes, tool results and thinking hidden, and what each turn sent the user from its `replies` entry, after that turn; older transcripts without `replies` entries fall back to the orchestrator's sent `message` calls to the user, held until the user next speaks or the end; the newest whole messages within `MAX_RESTORED_ROWS` (200) rendered rows at the current width, at least the newest one, led by a dim "… N earlier messages" (the summary note is not counted); messages are built cheaply for the whole branch but only those shown are laid out; the known live/restore differences are listed in its header), `questions.ts` (the orchestrator's questions, like Codex's pending questions: each page's `PageQuestions` are re-read on the inbox poll (and at open, when `load` also reads every question, answered ones too, for replies and restore) only when the questions dir's mtime changed or was under a second old at the last read, one read per page at a time; the active page's oldest open one shows above the status line via render.ts `questionRows` (pure: wrapped text with "(1 of N)", numbered options, "type your own answer", "skip (use default: …)" or "skip", and a hint per mode; on short terminals the hint wins, then a row of text, then the selected row; a menu or the project list wins over it). Modes: pick (an option or skip selected, input empty: "↑↓ or 1–9 choose · Enter pick · type to answer · Esc/Tab later"), answer ("answer>": the own-answer row, where a question without options starts: "Enter send · Esc clear · Tab later"), guard (a chat draft was in the input when the question showed: keys stay with chat, "send or clear your message to answer"), chat (nothing shown, or an agent view: only the count in the status line). `takes` is a pure predicate (plain ↑↓ Enter Esc Tab, and typing while picking or during the delay; Ctrl/Alt/Shift chords never; Ctrl+C always quits); `handle` syncs then acts: Enter picks the option or skips on the skip row, or sends the typed answer through `questions.clean` (refused with a dim "not sent: …"), or runs it as a command when its first word is a known one (`App.commands`, by the text up to the first space); 1–9 pick an option; typing on a row moves to the own answer; ↑↓ move between the answer's lines, then rows (never chat history); Esc never sends: it clears a typed answer, else puts the queue off like Tab, until a new id is open or `/questions` (which re-reads now and lists several). Enter, digits and typing are ignored for `questionDelayMs` (500) after a head first shows or keys come back from chat. The input is shared, so `sync` (on every draw and in `handle`) swaps buffers: the chat draft aside, a half-typed answer kept with its page; answers are not saved in the input history. After an answer or skip one dim line goes into the page's history (held in `page.held` while the reply's partial line streams; in an agent view seen after /back) and the next question shows. Closed elsewhere: a read that sees the head gone moves on quietly, or with typed text says "<Q> was answered elsewhere"; Enter on it says "already answered elsewhere; your answer was not sent"; either way typed text stays in the input as a chat draft (guarding the next question), never moved into it. Ids closed here (`mine`) are filtered from stale reads and not shown again when the orchestrator reads them; `app.inbox` checks `page.sent` first, so typed text that looks like an answer stays text. The status line adds "N questions" for the active page and "<name>: N questions" for each other page with open ones; `AppDeps.questions` stubs the store), `lines.ts` (`Line` and `lineRows`: a history line and its layout at a width), `history.ts` (input history: `projects/<id>/input-history`, one JSON string per line, newest last; each sent line is one `appendFile`, so concurrent TUIs interleave whole entries; loading keeps the newest `MAX_INPUT_HISTORY` (500), and the file is rewritten via temp file + rename (the temp file removed on failure) to those once it passes `COMPACT_AT` (1000) lines; `keepable` keeps only plain messages and /agents /models /help /projects /review-rounds /back /close /quit /keys /rename and /new without credentials in its URL, never /login or anything typed while signing in; blank lines and repeats of the last entry are not saved; never recreates a deleted project's folder; loaded on openPage), `markdown.ts` (pure, markdown → styled lines at a width, SGR and OSC 8 only: `takeBlocks` cuts the source into blocks (a line, a blank run, a fenced code block, a table) that each render alone (`renderBlock`), as a source line break stays a line break like Codex; headings bold (h1 underlined), `**`/`*`/`_`/`~~`/code spans (cyan), stricter than CommonMark so an opener never follows a letter or digit (snake_case, 2*3 stay literal); a closer skips escapes, code spans and nested spans (`*a **b** c*`); `-` bullets and numbers as written with hanging indents, nesting keeps the source indent; quotes behind a dim bar; code behind a dim gutter with the language as a label, cut only when wider than the screen; links (balanced parentheses allowed in the URL) as OSC 8 with the URL after in brackets when it differs from the text (Codex), empty text showing the URL, and only http(s)/mailto as OSC 8 (other schemes plain text); a table needs a delimiter row with as many cells as its header (GitHub); tables box-drawn with a bold header, the widest columns shrunk (`fitColumns`, at least 6 columns each) and their cells word-wrapped, else one "key: value" block per row (a header-only table lists its header cells); `wordWrap` carries styles and links across breaks; widths by Bun.stringWidth), `mdstream.ts` (`MarkdownStream`: `feed(chunk)` returns the blocks completed so far (a line at its newline, a code block at its closing fence, a table at the first non-row line, a possible table header at the next line), `pending` is the raw rest for the live region, `flush()` ends a reply; any chunking gives the same blocks as one feed), `render.ts` (pure, state → escape codes: `commit(lines, cols)` wraps finished lines for the scrollback; `live(frame, prev)` erases the previous live region (from the cursor's row up to its first row, then clear to the end of the screen), writes the partial line, a menu or the project list, the status line and the input area, which grows to a third of the screen and scrolls only when the cursor leaves it, and leaves the cursor in the input; `append` commits lines above it; `reprint` clears screen and scrollback and writes a page from scratch; the region always fits the screen; `sanitize` strips every escape but SGR and OSC 8 links, and every control but the tab, from committed and live text so stray tool output cannot move the cursor), `testing.ts` (`FakeScreen`, a faithful fake terminal for tests: visible screen plus scrollback, pending-wrap autowrap, wide characters, clamped cursor moves, and it throws on any escape or control it does not model or on a write that leaves synchronized output on or the cursor hidden), `editor.ts` (pure multi-line editing, independent of the frame: grapheme-aware insert/delete, word moves/deletes, wrap by display width → row/col, Up/Down between rows before history; Home/End and Ctrl+A/E/U/K act on the current line), `keys.ts` (legacy, xterm modifyOtherKeys and kitty key parsing, bracketed paste; `keyReader` holds a split escape sequence until the next read or an idle timeout, and keeps everything up to the paste end marker as paste text), `term.ts` (raw mode and bracketed paste; no alternate screen; while open, `exit`/SIGTERM/SIGHUP/uncaughtException handlers end synchronized output and paste mode, show the cursor, erase the live region (`eraseOnExit`, kept current by the app) and leave raw mode)
- `src/commands.ts` — what the slash commands do, separate from how the TUI shows them; includes the project list logic: `orderProjects`/`orderedProjects` (pinned first, each group sorted by display-name label), `togglePin`, `liveAgents` (tmux windows minus the idle shell), `exitWatchdog` (the TUI runs it for every open page on each inbox poll, via `App.watchPages`; tmux errors come back as null from `liveAgentsOrNull` so they never look like "all windows gone"; see `src/exits.ts`), `mergeWatch` (the merged-PR watcher from `src/merges.ts`, run next to it in `App.watchPages`; `AppDeps.merges` stubs it in tests), and `deleteProject` (removes `projects/<id>` and its pin; refused while agent windows are live)
- `src/providers/` — `Provider` interface over an Anthropic-shaped transcript; `anthropic.ts` (SDK) and `openai.ts` (Codex subscription Responses, translated; preserves encrypted reasoning and tool IDs). `providerFor(model)`: `claude*` → anthropic, else openai
- `src/accounts.ts` — subscription accounts only: config `account` selects a Claude profile, `openaiAccount` selects a Codex profile; empty means `default`. API keys, old saved keys, developer-platform profiles and billing fallbacks are unsupported.
- `src/claude-auth.ts` / `src/codex-auth.ts` — provider-specific OAuth login, import and refresh. `src/oauth.ts` shares PKCE callbacks, private atomic writes and cross-process locks. State is under `auth/anthropic/` or `auth/openai/`. Tests use temporary homes and fake tokens, never native credentials.
- `src/view.ts` — renders and follows a transcript for the terminal; `toolLine` is the dim "▸ name {input}" line the agent loop echoes for each tool call
- `src/agent.ts` — the loop; all three roles are this with a different prompt and tool set. `onInbox(msgs)` gets each batch of inbox messages as it is read (the orchestrator passes it to the TUI)
- `src/prompts.ts` — the three role system prompts: short behaviour lists, with the task-flow line and the complexity thresholds filled from config; on `[agent-exit]` the orchestrator tells the user and respawns the agent once, stopping if it exits the same way again; when the notice says "PR … merged" it does not respawn but starts what was waiting on that branch (the harness has already cleaned up, `src/merges.ts`). The orchestrator prompt stays under 2000 characters (a test checks it). `maxReviewRounds` (default 1; only an integer 0–100 is accepted, anything else falls back to the default; `loadConfig` also falls back to defaults, warning once on stderr, when config.toml does not parse) picks the task flow: 0 skips review (worker → reviewer with only "watch ci"); n ≥ 1 runs the loop below; if review n still finds problems, the worker gets one more pass with the notes, then the reviewer gets "watch ci" with no further review and the user hears what was left open. The orchestrator plans first (split as a table) and spawns nothing until the user says execute or dispatch. The cycle is orchestrator-driven: worker → reviewer (review mode: diff recon + `complexity`, no code changes) → worker again with notes, or reviewer again with "watch ci" (the only time it edits code; it pushes, opens the PR, runs `gh pr checks --watch`, fixes until green)
- `src/complexity.ts` — cyclomatic and Sonar cognitive complexity per function for JS/TS via `@babel/parser`; `src/tools/complexity.ts` is the reviewer's tool over it (changed files vs the default branch by default)
- `src/transcript.ts` — append-only JSONL with parent pointers. `branch()` is the current conversation: from the head back to the root or the latest summary, oldest first; `chain()` is its messages for the model. Besides messages, `meta` and `summary`, a `replies` entry records what a turn sent the user (appended by the orchestrator's `turn()` when it drains the user's inbox), so a restored page shows it where it showed live; it never reaches the model
- `src/tools/` — `bash`, `spawn`, `message`, `ask` (orchestrator only), `complexity` (reviewer only); keep the set small
- `src/questions.ts` — the orchestrator's question queue for the user (`questions/`, a file per question, inbox-style names, status open/answered/skipped, atomic writes, an exclusive `<id>.closed` claim so a question closes once, rolled back to open if the write or inbox send fails; input cleaned and capped by `clean`/`cleanQuestions`). `ask` appends and returns ids at once, never blocking; `list`/`answer`/`skip` are the API for the TUI (`src/tui/questions.ts`), and answering or skipping sends `[<id>] ...` to the orchestrator's inbox from `user`. A second answer or skip is refused
- `src/runner.ts` — worktree + tmux backend. `agentCommand` returns an argv that tmux execs directly (`new-window … -- argv`), never through the user's default shell: workers and reviewers run a fixed `sh -c` script with every value passed as a positional parameter (nothing is quoted or spliced); after a non-zero exit other than 70 (`SETTLED_EXIT`: run already closed) it runs `parallels agent-exit` with the same run id. `tmux.windows` returns null when tmux could not be asked, [] when the session or server is gone
- `src/proc.ts` — `run(argv, { cwd, timeoutMs, env? })`: spawn, read stdout/stderr, SIGKILL after the timeout; null when it could not start or timed out. Used by `dirtyCount` and `src/merges.ts`
- `src/exits.ts` — `[agent-exit]` notices to the orchestrator's inbox, from the agent's id, when a worker or reviewer stops without reporting. Senders: `supervise` in the agent process ("crashed: <error>", then exit 70; "finished without reporting"; "killed by SIGHUP/SIGTERM/SIGINT" from the in-memory state, then exit 128+n), `afterExit` (the shell follow-up: "exited (code n) without reporting"), and the TUI `watchdog` ("'s window is gone" for an agent seen live on an earlier poll; on its first check per project, a sweep of every run on disk: "stopped while the TUI was not watching"). `runs/<id>.json` holds the current run: run id, pid, state, last step and tool. Report rule: only the final report counts. A successful `message` to "orchestrator" sets state `reported`; any later tool call or inbox message sets it back to `running`, so an interim "starting…" message does not silence a later notice. A run is closed by an exclusive create of `runs/<id>.<run>.exit`, by whoever sends its notice (or silently, when it ended on a report), so each run gets at most one notice; claims are pruned only after a day, so an old run's follow-up still sees its claim after a quick respawn. The watchdog skips a check when tmux could not be asked and only sends once the run's pid is dead (`process.kill(pid, 0)`). Notices carry role, branch, last step and tool, the error, and the uncommitted count, computed only when a notice is built: `git --no-optional-locks status --porcelain` with a 3s hard timeout (1s in a signal handler), "unknown" on timeout; the watchdog runs it in `worktrees/<slug(branch)>`
- `src/merges.ts` — merged PRs. `mergeWatcher({ gh?, repo?, live, kill?, alive?, dirty?, now?, everyMs?, waitMs? })` returns `check(project)`, which the TUI runs for every open page on each inbox poll (`checkProject`: at most every `MERGE_POLL_MS` (30s) per project, one check per project at a time). Only a GitHub origin is checked (`originRepo`/`githubRepo` from `git remote get-url origin`); `ghMerged` runs `gh pr list --repo <owner/name> --state merged --limit 100 --json number,headRefName,url,mergedAt,headRefOid,isCrossRepository` with a 20s hard timeout and returns null on any failure (the check is then skipped quietly, as when tmux cannot be asked). Never touched: PRs from forks (`isCrossRepository`), main/master/HEAD, the checked-out branch, origin's default branch (`refs/remotes/origin/HEAD`, cached per project), closed or missing PRs. A merged PR is handled when its branch (by `slug`) still has a worktree, agent windows, transcripts or runs/ files and the worktree is not newer than `mergedAt` (`reused`: the name was reused). Claims: `projects/<id>/merged/<n>`, linked in exclusively from a temp file; "started" (with a timestamp and the agents running) until the notice is out, then "handled" (or "kept: …", "nothing to do", "branch reused after the merge", all final), rewritten by temp + rename; a "started" claim older than `STALE_CLAIM_MS` (10 min: a crash or a failed send) is taken over once (`<n>.retry-<ts>`), keeping its running list for the notice. Before stopping anything (`notThePR`): the worktree's `symbolic-ref --short HEAD` must be the PR's branch by name, and the local tip must be `headRefOid` or its ancestor (`merge-base --is-ancestor`, fetching the head when unknown); otherwise nothing is stopped and the notice says "<agents> left running: …; kept: worktree is on <x>" / "kept: branch has commits not in the PR". Then: claim the agents' current runs (exits.ts `claim`, so their own exit paths and the watchdog stay silent), kill their windows, wait up to 5s for their pids; keep everything if a pid lives on ("kept everything: an agent process is still running") or a new window or run id appeared ("a new agent started on the branch"), keep the worktree, branch, transcripts and runs on uncommitted changes or an unknown count; otherwise `removeBranches` (`git worktree remove --force`, which also deletes ignored files such as .env; `branch -D`; `push origin --delete`, "remote ref does not exist" ignored) and `removeAgentFiles` (transcripts, inboxes, runs/ files but the just-closed runs' `.exit` claims). `git pull --ff-only` in repo/ after a stop, failure ignored. One notice per PR: `[agent-exit] worker-x, reviewer-x stopped: PR #n (<branch>) merged (<url>); cleaned up` (or "no agents running", "kept worktree: N uncommitted changes", "cleaned up, except: …"). A send that fails before the stop drops the claim; after the stop it stays "started" for the takeover
- `src/inbox.ts` — one FIFO inbox per agent (`inbox/<agent>/`, a file per message); with the transcripts, the only state on disk. `message` sends to any address: `orchestrator`, `user`, or an agent id. Agents read their inbox before the first request, after each tool call (delivered with the tool results, never interrupting one), and after every turn, and keep going while messages arrive. `format` tags each message `[sender]`; `parseFormatted` reads that back (for restoring old turns only), taking only real sender ids (`user`, `orchestrator`, `worker…`, `reviewer…`) as tags.

Each agent gets its task from the first user message (spawn's brief or the inbox) and the tool descriptions, so keep those descriptions precise. The system prompt is the provider's Claude Code/Codex identity line followed by the role prompt from `src/prompts.ts`; keep those prompts short lists. Agents' messages to the orchestrator are full reports with no length limit (the worker and reviewer prompts, the `message` description and spawn's `prompt` description say so); only the orchestrator's output to the user is concise.

Rules:

- All state lives under `~/.parallels` (`src/config.ts` has the layout). A project's id is its folder name and never changes; the status line shows its display name (`displayName` in `src/commands.ts`). `PARALLELS_HOME` overrides it in tests.
- No task list. Everything is keyed by branch: `spawn(prompt, branch, role)` seeds `transcripts/<role>-<branch>.jsonl` and starts the agent in `worktrees/<branch>`.
- Agents only know their cwd. Never read the host or another worker's worktree.
- Tool results are byte-capped when appended to the transcript.
- Prefer `Bun.file`, `Bun.$`, and `bun:test` over npm packages.
