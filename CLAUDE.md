# parallels

A light-context agent harness: orchestrator → worker → reviewer loop, each agent in a tmux window. See docs/PLAN.md for the design.

Bun + TypeScript. Use `bun` for everything (`bun test`, `bun run check`, `bun src/cli.ts`). No Node, npm or vite.

Layout:

- `src/cli.ts` — `start [project] [directory]`, `msg`, `agent`, `agent-exit` (internal: the follow-up after a non-zero agent exit), `version` commands. `start` opens the sticky-bar TUI; run inside a git repo, it opens the `orch-xxxx` project bound to the canonical original checkout, creating one if none exists (`repoHere` / `projectFor` in `src/commands.ts`), and Ctrl+N creates another conversation in that checkout
- `src/tui/` — ruled sticky project/display tabs plus model/effort/fast/directory/remote header and bottom input/status/panels, with a scrollable conversation between them. `chrome.ts` windows real display identities around the active tab and bounds header metadata; `sticky.ts` lays out the viewport, anchors resize to source-part/grapheme positions (neutral separators stay separate; table interiors use the table start) and diffs screen rows; Page Up/Page Down and SGR/classic X10 mouse wheel scroll without moving the bars. `app.ts` caches rendered history, follows `/agents`, throttles frames (16ms), debounces resize (120ms), and routes console output into history. Startup restores full `Transcript.history()` via the orchestrator's entries accessor without a display cap, never bounded model context. Rendered history is cached; each normal frame slices only visible rows, including the transient tail. `render.ts` supplies the bottom layout: bounded queued-input previews immediately above the boxed input, grouped counts, then every menu/project list/USER inbox (Tasks + Questions). Queued previews are a read-only projection of `Page.sent` plus sign-in-held text, oldest first; one row per prompt (`↵` for newlines, `…` for clipping), a shown/total heading and hidden count, at most six rows / a third of the footer budget without shrinking the editor. No persistent shortcut row; explicit panels retain hints. `/help` is an explicit, Esc-dismissible scrollable footer panel below the composer/counts (never transcript history); `help.ts` groups table-provided command metadata and keyboard help, with aligned/wrapped labels and quieter diagnostics. Help owns scrolling/typing while open, preserves chat/answer drafts, and closes on page/menu/project changes; Ctrl+Q explicitly opens Inbox Questions (or closes that section). Transient selected-session activity and running tools belong only to the scrollable conversation tail, never the footer, exit transcript or restore. `inputGeometry` drives both rendering and vertical editing. Tiny terminals prioritize input and status; hidden modals still own keys until Esc. `editor.ts` keeps grapheme-aware editing/history and cursor-aware input scrolling. `style.ts` shades user messages/composer (10%), not the ruled header, with 256-colour fallback, truecolor and NO_COLOR support. `term.ts` owns alternate-screen, paste and always-on SGR mouse/drag modes (in-app conversation selection, explicit Ctrl+O copy; native link gestures are terminal-dependent) and restores them on exit/crash; normal exit prints the active transcript to the primary screen. It asks OSC 11 once and waits for the reply/300ms timeout before showing history; pending replies drain safely on close. `keys.ts` frames raw bytes before decoding Unicode, keeps OSC and SGR/classic X10 mouse reports out of typed text, and disambiguates lone Escape with a 25ms wait outside the background query. Ctrl+G opens `/keys` without replacing the active draft; Esc ends diagnostics without clearing it.
- USER inbox: `/inbox` opens Tasks; Ctrl+Q and compatible `/questions` open Questions. Shift+Tab switches sections without answering; Esc/plain Tab dismiss. `render.ts` keeps small Tasks/Questions tabs below composer/counts; `task-inbox.ts` renders the existing Name | Summary | Status | PR link list (72+ columns, labelled records below). Status is exactly one plain label: stored attention.kind first, otherwise lifecycle (`ready_to_merge` → `ready to merge`), no prefix, reason or extra line; storage stays unchanged and global warnings stay visible; `tui/questions.ts` retains its own controller/store, explicit answer delivery and silent durable Skip path, opening/new-head guard, single-flight delivery and per-page chat/answer cursors. No migrations, task reconstruction, provider calls or queue consumption on navigation. Footer `Inbox N` is unanswered questions only; `?` is unknown/failed, `(+N elsewhere)` counts other open pages (compact on narrow screens, `?` for unknowns). Agent and prompt counts/previews remain separate. `/agents` is unchanged/separate; Questions in agent views is guarded, never redirected to that agent. Page switches close Inbox without dropping drafts; captured ownership suppresses stale reads/answer UI results and stale agent-menu loads. Questions read failures retain a visibly stale snapshot, not a fabricated zero; unreadable/malformed records now fail closed. `render.plainText` strips terminal controls/styles/links/bidi from untrusted fields/errors; task PR links alone use validated canonical OSC 8. See docs/TASK_INBOX.md.
- TUI history: `lines.ts` `historyRows` owns neutral inter-message spacing for incremental commits and reprints. `MarkdownStream.feedLines/flushLines` mark parser blocks with `continuation: true` after the first block of one logical assistant message; paragraph/quote/list source lines never imply new messages. A fresh response/turn starts a new block. Restore uses the same stream metadata; `/agents` joins text blocks of one assistant entry before rendering. User continuation rows and tool label/result pairs remain together. Existing markdown blanks are not doubled. `wrap` replays foreground/dim/bold SGR across soft wraps, and commit resets unrelated output. FakeScreen models backgrounds plus foreground/intensity. `restore.ts` supports bounded previews retaining newest whole messages within the actual spaced display budget, including omission note and boundary separators (newest oversize message always retained); the live page uses `Infinity` so no originals are accessible only after exit; summary and report/question-reply parsing remain shared with live delivery.
- TUI input delivery: Enter sends inbox text and tracks `Page.sent` by immutable `inputId` (echoed unchanged through the inbox) until `onInbox` consumes it at the existing tool-batch/response boundary. Only then are userLines shown; queued counts include inbox and sign-in-held text, external users are not suppressed, locally answered questions are not duplicated. Input history remains per project and excludes secrets. Sign-in queue ownership transfers one message at a time to send; new submissions during a delayed transfer append to the same owner instead of overtaking older input; failed texts are explicitly reported and later messages/pages still get attempted. `questions.ts` is opt-in via Ctrl+Q or `/questions`: arrivals only update counts. Pick/answer/chat modes, no guard mode. Esc/Tab/Ctrl+Q closes without answering/skipping and preserves chat/answer drafts. Chat text/cursors are page-owned in a WeakMap (no-page text separately), not a shared buffer carried between projects; answers remain page-owned too. Only Enter on skip removes the question from Inbox, durably retaining its skipped record; it sends no message, applies no default and never wakes/resumes an agent. The optional default is only a suggestion for an explicit answer; silence/dismissal never applies it or grants approval. Skip feedback is local only; legacy delivered skip/default transcripts still restore unchanged. External closure restores the ORIGINAL chat draft and reports the orphan answer separately, never assigning it to the next question. Emptying the queue closes it. The half-second accidental-key guard and #45 in-flight-close poll guard remain. Menus/projects take precedence over questions.
- TUI model/settings: `/models` uses project-aware choices, captured project identity, shared project-state locks, modelAgents/saveModel hooks, generation checks and Cancel-default confirmation when live subagents exist; `/effort` and `/fast` remain project settings with provider validation. `readModel` defaults to `effectiveModel(project)` for both startup and refresh while retaining AppDeps.projectModel injection. Successful commitModel awaits refreshHeader(captured page). A WeakMap per-page refresh generation rejects late results after newer reads; removed/reopened Page objects cannot be updated. Rendering only reads cached Page.model. Model resolver/settings and onTool/onToolResult are both forwarded through orchestrator/agent. Commands/key layers, /rename, project create/delete/pin, /accounts/login and /review-rounds remain table-driven with their preexisting guards; no-page feedback persists across redraws.
- `src/commands.ts` — what the slash commands do, separate from how the TUI shows them; includes the project list logic: `orderProjects`/`orderedProjects` (pinned first, each group sorted by display-name label), `togglePin`, `liveAgents` (tmux windows minus the idle shell), `exitWatchdog` (the TUI runs it for every open page on each inbox poll, via `App.watchPages`; tmux errors come back as null from `liveAgentsOrNull` so they never look like "all windows gone"; see `src/exits.ts`), `mergeWatch` (the merged-PR watcher from `src/merges.ts`, run next to it in `App.watchPages`; `AppDeps.merges` stubs it in tests), and `deleteProject` (removes project state, clean managed worktrees and its pin; preserves the original checkout and local branches; refused while agents are live/unknown or worktrees have local files)
- `src/providers/` — `Provider` interface over an Anthropic-shaped transcript; `anthropic.ts` (SDK) and `openai.ts` (Codex subscription Responses, translated; preserves encrypted reasoning and tool IDs). `providerFor(model)`: `claude*` → anthropic, else openai
- `src/accounts.ts` — subscription accounts only: config `account` selects a Claude profile, `openaiAccount` selects a Codex profile; empty means `default`. API keys, old saved keys, developer-platform profiles and billing fallbacks are unsupported.
- `src/claude-auth.ts` / `src/codex-auth.ts` — provider-specific OAuth login, import and refresh. `src/oauth.ts` shares PKCE callbacks, private atomic writes and cross-process locks. State is under `auth/anthropic/` or `auth/openai/`. Tests use temporary homes and fake tokens, never native credentials.
- `src/view.ts` — renders and follows a transcript for the terminal; `parts` gives tool calls and results as `{ call }` / `{ result }` parts for the TUI to pair (tools.ts `Calls.absorb`); `render` shows them as plain "⏺" / "⎿" lines
- `src/toolview.ts` — how a tool call shows, like Claude Code, shared by agent.ts, the TUI, restore.ts and view.ts so live and restored pages match: `toolLabel` ("Bash(git status)": a per-tool formatter table — bash's command, message's `to: first words`, spawn's `branch, role`, complexity's files, ask's question — else `Name(first string arg)`), `toolSummary` (one line: bash "N lines" / "no output" / "exit N: <last nonzero error-looking line>" / "timed out after …", spawn "spawned <id>", otherwise the result's first line; is_error results and a tool's "refused: …" are failures), `toolView` → the `{ tool, summary, failed }` history Line
- `src/agent.ts` — the loop; all three roles are this with a different prompt and tool set. `onInbox(msgs)` gets each batch of inbox messages as it is read (the orchestrator passes it to the TUI); `onTool({id, name, input})` / `onToolResult({id, ok, text})` get each tool call as it starts and ends (threaded through createOrchestrator and the app's `openOrchestrator(…, tools)` like onInbox); without them (workers and reviewers in tmux) `write` gets the "⏺ Label" line and its "  ⎿  summary" as plain lines
- `src/prompts.ts` — the three role system prompts: short behaviour lists, with the task-flow line and the complexity thresholds filled from config; on `[agent-exit]` the orchestrator tells the user and respawns the agent once, stopping if it exits the same way again; when the notice says "PR … merged" it does not respawn but starts what was waiting on that branch (the harness has already cleaned up, `src/merges.ts`). Role prompts stay under 2200 characters (a test checks it). `maxReviewRounds` (default 1; only an integer 0–100 is accepted, anything else falls back to the default; `loadConfig` also falls back to defaults, warning once on stderr, when config.toml does not parse) picks the task flow: 0 skips review (worker → reviewer with "watch ci"); n ≥ 1 bounds substantive review; trivial wording/formatting in README/docs/comments may go directly to structured `reviewMode: "watch-ci"` with a risk rationale and bounded requested-text/link checks, without a code-review round; if review n still finds problems, the worker gets one more pass with the notes, then the reviewer gets "watch ci" with no further review and the user hears what was left open. The orchestrator plans first (split as a table) and spawns nothing until explicit execution authorization (execute, dispatch or a clear chat equivalent). The cycle is orchestrator-driven: worker → reviewer (review mode: actual diff/risk assessment, relevant checks and `complexity` for changed JS/TS logic where relevant, no code changes) → worker again with notes, or reviewer again with "watch ci" (the only time it edits code; it pushes, opens the PR, runs `gh pr checks --watch`, fixes until green). Workers and reviewers choose checks proportionate to the diff, not full app suites or metrics for pure editorial changes. Semantic prompt/config/security changes and executable examples need substantive review even in Markdown; extension alone never proves low risk. A misclassified substantive watch-ci diff returns to the orchestrator when rounds are enabled, respecting the cap and disclosing exhausted-budget exceptions. Publication/no CI is not readiness: validate the exact clean PR head with evidence before `task ready`. Only explicitly tagged review dispatches count as rounds.
- `src/complexity.ts` — cyclomatic and Sonar cognitive complexity per function for JS/TS via `@babel/parser`; `src/tools/complexity.ts` is the reviewer's tool over it (prefer explicit relevant files; otherwise changed files vs the default branch). It scores all functions in selected files, not metric deltas: unchanged functions are baseline context, not regressions. Config thresholds remain authoritative; unsupported/failed analysis is not zero complexity
- `src/transcript.ts` — append-only JSONL with parent pointers. `branch()` is the current conversation: from the head back to the root or the latest summary, oldest first; `chain()` is its messages for the model. Besides messages, `meta` and `summary`, a `replies` entry records what a turn sent the user (appended by the orchestrator's `turn()` when it drains the user's inbox), so a restored page shows it where it showed live; it never reaches the model
- `src/tools/` — six tools: `bash`, `spawn`, `message`, `ask` (orchestrator only), `complexity` (reviewer only), `web_search` (all roles; native subscription search, no fallback). Role counts: orchestrator 5, worker 3, reviewer 4. Search receives the resolved model/provider/settings snapshot for its tool batch; see docs/WEB_SEARCH.md for bounds, source attribution and unverified live-account compatibility. Keep the set small; spawn's description holds the reuse-or-new-branch rule; the orchestrator prompt points at it; spawn refuses while an agent on that branch is live (`Runner.running`, polled every 250ms for up to 20s first; null from tmux lets it go ahead)
- `src/questions.ts` — the orchestrator's question queue for the user (`questions/`, a file per question, inbox-style names, status open/answered/skipped, atomic writes, an exclusive `<id>.closed` claim so a question closes once, rolled back to open if the write or inbox send fails; input cleaned and capped by `clean`/`cleanQuestions`). `ask` appends and returns ids at once, never blocking; `list`/`answer`/`skip` are the API for the TUI (`src/tui/questions.ts`), and only explicit answering sends `[<id>] ...` to the orchestrator's inbox from `user`. Skip persists `skipped` without any delivery item, pending user input, default application or wakeup/resume, even when the orchestrator is paused/cancelled. Malformed records/IDs fail closed; if rollback itself fails, the exclusive claim stays held rather than risk duplicate delivery. A second answer or skip is refused
- `src/runner.ts` — worktree + tmux backend. `agentCommand` returns an argv that tmux execs directly (`new-window … -- argv`), never through the user's default shell: workers and reviewers run a fixed `sh -c` script with every value passed as a positional parameter (nothing is quoted or spliced); after a non-zero exit other than 70 (`SETTLED_EXIT`: run already closed) it runs `parallels agent-exit` with the same run id. `tmux.windows` returns null when tmux could not be asked, [] when the session or server is gone
- `src/proc.ts` — `run(argv, { cwd, timeoutMs, env? })`: spawn, read stdout/stderr, SIGKILL after the timeout; null when it could not start or timed out. Used by `dirtyCount` and `src/merges.ts`
- `src/exits.ts` — `[agent-exit]` notices to the orchestrator's inbox, from the agent's id, when a worker or reviewer stops without reporting. Senders: `supervise` in the agent process ("crashed: <error>", then exit 70; "finished without reporting"; "killed by SIGHUP/SIGTERM/SIGINT" from the in-memory state, then exit 128+n), `afterExit` (the shell follow-up: "exited (code n) without reporting"), and the TUI `watchdog` ("'s window is gone" for an agent seen live on an earlier poll; on its first check per project, a sweep of every run on disk: "stopped while the TUI was not watching"). `runs/<id>.json` holds the current run: run id, pid, state, last step and tool. Report rule: only the final report counts. A successful `message` to "orchestrator" sets state `reported`; any later tool call or inbox message sets it back to `running`, so an interim "starting…" message does not silence a later notice. A run is closed by an exclusive create of `runs/<id>.<run>.exit`, by whoever sends its notice (or silently, when it ended on a report), so each run gets at most one notice; claims are pruned only after a day, so an old run's follow-up still sees its claim after a quick respawn. The watchdog skips a check when tmux could not be asked and only sends once the run's pid is dead (`process.kill(pid, 0)`). Notices carry role, branch, last step and tool, the error, and the uncommitted count, computed only when a notice is built: `git --no-optional-locks status --porcelain` with a 3s hard timeout (1s in a signal handler), "unknown" on timeout; the watchdog runs it in `worktrees/<slug(branch)>`
- `src/merges.ts` — merged PRs. `mergeWatcher({ gh?, repo?, pr?, live, kill?, alive?, dirty?, now?, everyMs?, waitMs? })` returns `check(project)`, which the TUI runs for every open page on each inbox poll (`checkProject`: at most every `MERGE_POLL_MS` (30s) per project, one check per project at a time). Only a GitHub origin is checked (`originRepo`/`githubRepo` from `git remote get-url origin`); `ghMerged` runs `gh pr list --repo <owner/name> --state merged --limit 100 --json number,headRefName,url,mergedAt,headRefOid,isCrossRepository` with a 20s hard timeout and returns null on any failure (destructive cleanup is then skipped quietly, as when tmux cannot be asked; registered tasks still get exact-PR refresh). Never touched: PRs from forks (`isCrossRepository`), main/master/HEAD, the checked-out branch, origin's default branch (`refs/remotes/origin/HEAD`, cached per project), closed or missing PRs. A merged PR is handled when its branch (by `slug`) still has a worktree, agent windows, transcripts or runs/ files and the worktree is not newer than `mergedAt` (`reused`: the name was reused). Claims: `projects/<id>/merged/<n>`, linked in exclusively from a temp file; "started" (with a timestamp and the agents running) until the notice is out, then "handled" (or "kept: …", "nothing to do", "branch reused after the merge", all final), rewritten by temp + rename; a "started" claim older than `STALE_CLAIM_MS` (10 min: a crash or a failed send) is taken over once (`<n>.retry-<ts>`), keeping its running list for the notice. Before stopping anything (`notThePR`): the worktree's `symbolic-ref --short HEAD` must be the PR's branch by name, and the local tip must be `headRefOid` or its ancestor (`merge-base --is-ancestor`, fetching the head when unknown); otherwise nothing is stopped and the notice says "<agents> left running: …; kept: worktree is on <x>" / "kept: branch has commits not in the PR". Then: claim the agents' current runs (exits.ts `claim`, so their own exit paths and the watchdog stay silent), kill their windows, wait up to 5s for their pids; keep everything if a pid lives on ("kept everything: an agent process is still running") or a new window or run id appeared ("a new agent started on the branch"), keep the worktree, branch, transcripts and runs on uncommitted changes or an unknown count; otherwise `removeBranches` (`git worktree remove --force`, which also deletes ignored files such as .env; `branch -D`; `push origin --delete`, "remote ref does not exist" ignored) and `removeAgentFiles` (transcripts, inboxes, runs/ files but the just-closed runs' `.exit` claims). `git pull --ff-only` only for legacy managed clones after a stop, failure ignored; never pull an original checkout in background cleanup. One notice per PR: `[agent-exit] worker-x, reviewer-x stopped: PR #n (<branch>) merged (<url>); cleaned up` (or "no agents running", "kept worktree: N uncommitted changes", "cleaned up, except: …"). A send that fails before the stop drops the claim; after the stop it stays "started" for the takeover
- `src/inbox.ts` — one FIFO inbox per agent (`inbox/<agent>/`, a file per message; puts to one inbox from one process land one after another, in send order); distinct from the task registry and user question/prompt queues. `message` sends to any address: `orchestrator`, `user`, or an agent id. Agents read their inbox before the first request, after each tool call (delivered with the tool results, never interrupting one), and after every turn, and keep going while messages arrive. `format` tags each message `[sender]`; `parseFormatted` reads that back (for restoring old turns only), taking only real sender ids (`user`, `orchestrator`, `worker…`, `reviewer…`) as tags.

Each agent gets its task from the first user message (spawn's brief or the inbox) and the tool descriptions, so keep those descriptions precise. The system prompt is the provider's Claude Code/Codex identity line followed by the role prompt from `src/prompts.ts`; keep those prompts short lists. Agents' messages to the orchestrator are full reports with no length limit (the worker and reviewer prompts, the `message` description and spawn's `prompt` description say so); only the orchestrator's output to the user is concise.


Workspace ownership:

- `src/workspace.ts` binds new projects to the original checkout on its default branch; `repository.json` stores the canonical path, branch and unique worktree namespace. Never clone, switch or stash it automatically. Main-agent turns recheck the branch. Older clone-based projects remain unchanged; do not silently migrate their active worktrees/history.
- `paths.repo` resolves the binding, falling back to `projects/<id>/repo` only for legacy projects. `paths.worktree` resolves beside the original checkout (`<checkout>.parallels-worktrees/<uuid>/<slug>`), falling back to legacy paths. New projects cannot overlap their state directory. Checkouts sharing a path share a turn lock across conversations.
- Workers branch from the original default branch; reviewers reuse the same task worktree. Validate common Git storage and branch before reusing/removing a worktree. Shared repo-local Git settings include login updates; untracked/ignored files are not automatically copied.
- `src/launch-environment.ts` passes the current launch environment through a private, self-deleting shell file, clearing stale tmux environment while preserving its window identity. Never put credentials in argv or tmux options.
- Updater authentication: `src/git-credentials.ts` filters normal system/global Git configuration to `credential.*` only for the verified fetch. Keep helper order, empty resets, scoped settings and local precedence. A private temporary config is removed on success/failure; never log config output or pass credential values in argv. Global URL rewrites/hooks and inherited repository/config overrides remain disabled. Tests use fixture config/helpers, never native credentials.

Rules:

- Harness state lives under `~/.parallels` (`src/config.ts` has the layout). A project's id is its folder name and never changes; the header tab shows its display name (`displayName` in `src/commands.ts`). `PARALLELS_HOME` overrides it in tests.
- Structured task inbox: `src/tasks.ts` persists authorized tasks in per-project `tasks.json` (UUIDs, stages, PR identity/head, exact runs, attention, retained merge history). Register new work before `spawn(prompt, branch, taskId, role)`. Retries, review/CI corrections and fixes to the same unmerged PR keep its ID and branch, including after a ready report; refresh PR state before resuming and revalidate readiness after changes. Separate follow-ups get new IDs and need new branches after PR publication. Transcripts/windows/worktrees remain branch-keyed. No prose-derived state or task scheduling. See `docs/TASK_INBOX.md` for schema, query API and lifecycle producers.
- Agents only know their cwd. Never read the host or another worker's worktree.
- Tool results are byte-capped when appended to the transcript.
- Prefer `Bun.file`, `Bun.$`, and `bun:test` over npm packages.


Project model switching and request settings:

- `src/project-model.ts`: `effectiveModel(project)` / `saveProjectModel(project, model, identity?)`; project override with unchanged global fallback. `projectModelResolver` returns model/provider/settings before every request in every production agent.
- `src/project-settings.ts`: `effectiveSettings(project, model)`, `saveProjectSettings(project, model, patch)`, `effortCommand`, `fastCommand`. `/effort [level|default]` and `/fast [on|off]` are project/exact-model scoped, with conservative endpoint compatibility (`model-capabilities.ts`), backend defaults when absent, no picker; current values appear in the header. Unknown explicit capabilities refuse without saving.
- `src/project-state.ts`: invocation queue + cross-process lock shared by managed project create/delete and model/settings saves; captured directory identity refuses old-generation commits after deletion/recreation. Never steal uncertain stale locks.
- `/models` counts actual live windows using `liveAgentsOrNull` (injectable `AppDeps.modelAgents`); unknown liveness refuses. Model async generations cancel stale results. No-page settings commands explain rather than open a project. No-page feedback survives redraw until a page opens. `AppDeps.saveModel` is the injectable commit boundary; once persistence starts the captured project owns the save, not the selected page.
- In-flight calls/tools finish. Failed turns retain drained history and require another message to resume; changing settings never retries a task or restarts exited workers/reviewers. Provider-load errors are explicit. Cross-provider adapter sanitizer and fake tests do not guarantee live service acceptance of all historic reasoning/multimodal blocks.
- See `docs/MODEL_SETTINGS.md` for exact semantics, verified SDK/official endpoint sources, allowed model/effort/tier subset, tests and limitations.

Compaction: see docs/COMPACTION.md. `/compact` and auto compaction resolve foreground model/provider/settings once per safe boundary; orchestrator memory uses its separate configured Luna summarizer. Model context uses `Transcript.chain()`; UI replay uses `Transcript.history()` via orchestrator `entries()`. Summaries are best-effort/lossy. Orchestrators use background rolling memory and scoped SQLite search/read via task; workers/reviewers pin their complete original task. Both preserve original disk/UI entries and exact receipts. Transcript records now publish complete byte-preserving file images via staged fsync/close + rename, with explicit post-commit directory durability warnings.

Structured task merge observations are separate from destructive cleanup: exact repository/PR matches archive active rows before cleanup claims or tmux/worktree checks. Task records remain. `src/github.ts` validates explicit PR snapshots; readiness requires reviewer attestation plus a matching clean local/published head, not PR creation or agent exit. `listTasks` is the narrow typed data source for the Inbox Tasks table. See `docs/TASK_INBOX.md`.

Context clearing: `/clear` is a local Cancel-default footer confirmation, never a user/model message or provider request. Refuse in agent views, while running/compacting, or with any raw durable/paused inbox or TUI held/persisting input; recheck on confirmation. Captured Page/directory identity and the project-state lock protect ownership. Page/menu changes, Escape/Ctrl+C and resize invalidate confirmation without touching drafts. Input recall excludes `/clear`. `Orchestrator.checkClear()` / `clear(signal?)` append an explicit `context-boundary` with intact parent links using transcript publication; chain/branch stop before it, history/UI/exit replay ignore it and retain originals. Compaction's original-task pin and retrieval warning are scoped after the latest boundary, never resurrecting pre-clear context. Orchestrator inbox publication now shares the project lock with clear; later external sends remain new input. No inbox draining, retries, resume or worker restarts. See docs/COMPACTION.md for commit/cancellation semantics and the cooperative cross-process locking and mixed-version limitations in docs/SESSION_REFRESH.md.

Session refresh/queues: `/refresh`, prompt submission (including busy/login-held input), and passive polling reconcile shared local state without calling `say`, `turn`, tools, watchdogs, or restarts. Submission starts before refresh and never awaits it; local active context reload waits until idle. `onRefresh` restores shared history before local streaming. `Transcript.refresh/consumed`, `inbox.consume`, and `storage-lock.ts` implement locked snapshot/publication and exact committed input/delivery receipts; no text matching or disappearance-based acknowledgements. Orchestrators own one cross-process turn lock, refresh before a turn, and require fresh consumed input rather than replaying history after cleanup or errors. Clear/delete also honor turn ownership. No time-based stale-lock stealing; mixed old/new processes cannot provide these guarantees. See docs/SESSION_REFRESH.md (including branch reviewer constraints).

Clipboard images: see docs/IMAGE_ATTACHMENTS.md. `images.ts` owns validated scoped PNG
storage, immutable image-input journals and provider materialization; `clipboard.ts`
reads on explicit Ctrl+V only, with system JXA or existing Linux tools. Keep tests
on injected/isolated fixtures, never the live clipboard. Inbox receipts still own
consumption. `spawn`/`message` attachments explicitly forward IDs from the sender's
current context epoch. Compaction retains real references and budgets pixels, not
base64, including #74 rolling checkpoints. `image-history.ts` sanitizes text-only summaries/search, while SQLite raw entries retain scoped references. `rolling-images.test.ts` covers combined checkpoint/history/provider/forwarding/clear behavior.
