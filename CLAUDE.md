# parallels

A light-context agent harness: orchestrator → worker → reviewer loop, each agent in a tmux window. See PLAN.md for the design.

Bun + TypeScript. Use `bun` for everything (`bun test`, `bun run check`, `bun src/cli.ts`). No Node, npm or vite.

Layout:

- `src/cli.ts` — `start [project] [git-url]`, `msg`, `agent`, `version` commands. `start` opens the inline TUI; run inside a git repo, it opens the `orch-xxxx` project cloned from that repo's origin, creating one if none exists (`repoHere` / `projectFor` in `src/commands.ts`), and Ctrl+N clones from it too
- `src/tui/` — the bare inline TUI, like Claude Code and Codex: no alternate screen; finished lines of the active page go once into the terminal's own scrollback (scroll with the terminal; no PgUp/PgDn), and only the live region at the bottom (the partial streaming line, a menu or the project list, the status line, the input area) is redrawn; switching pages, resizing, `/agents` and `/back` clear the screen and scrollback and reprint that page (or transcript); output for a page that is not active only goes into its history; quitting drops the live region and leaves the output with the cursor on a fresh line. `app.ts` (one page per orchestrator; Ctrl+N starts `orch-xxxx` at once, `/rename <name>` sets a display name only (saved in `projects/<id>/name`; the folder, id, tmux session and running agents are untouched, so it works mid-turn; names must be unique, printable, no bidi overrides; `/new <id>` and Ctrl+N's orch-xxxx never reuse another project's display name), Ctrl+Z / Ctrl+X switch, Ctrl+B or `/projects` (Ctrl+B is tmux's prefix) toggles a list of every project, drawn like the /models menu above the status line: ↑↓/jk, Enter opens and closes it, `p` pins (config `pinned`), `d` deletes after a plain y (Ctrl/Alt chords do nothing in the list), Esc closes; rows show each project's display name (`/rename`) while open, pin, delete and live checks use its id; `AppDeps.projects` stubs its tmux checks in tests; `/keys` echoes what the terminal sends; `/help` lists the commands: `/agents` picks a transcript to view live, `/back` leaves the agent view (listed only there), `/models [id]`, `/review-rounds [n]` (shows or saves `maxReviewRounds`; the orchestrator re-reads config every turn, so it applies from its next turn), `/accounts`, `/login claude [profile] | codex [profile]` (aliases: anthropic/openai), `/new [name] [git-url]`, `/close` closes the whole page, `/quit`. Every command works at any time: mid-turn, while viewing an agent (plain text there is refused until `/back`), and while signing in (a second `/login` is refused; plain text is held in the app and sent as soon as sign-in succeeds, or dropped with a note if it fails); a dimmed status line above the input shows the page's display name, remote and the number of open pages, led while a turn runs by a braille spinner "thinking…/working… Ns" (a live `/agents` view shows "following <agent>" instead, re-checked via tmux (`liveAgents`) about once a second, one call per project at a time), and "N busy" for busy background pages; a 100ms timer animates it only while something is busy — `AppDeps.clock` and `agents` are injectable for tests; the status text is built in app.ts, apart from the layout), `render.ts` (pure, state → escape codes: `commit(lines, cols)` wraps finished lines for the scrollback; `live(frame, prev)` erases the previous live region (from the cursor's row up to its first row, then clear to the end of the screen), writes the partial line, a menu or the project list, the status line and the input area, which grows to a third of the screen and scrolls only when the cursor leaves it, and leaves the cursor in the input; `append` commits lines above it; `reprint` clears screen and scrollback and writes a page from scratch; the region always fits the screen), `testing.ts` (a tiny fake terminal for tests that applies those escape codes to a scrollback buffer), `editor.ts` (pure multi-line editing, independent of the frame: grapheme-aware insert/delete, word moves/deletes, wrap by display width → row/col, Up/Down between rows before history; Home/End and Ctrl+A/E/U/K act on the current line), `keys.ts` (legacy, xterm modifyOtherKeys and kitty key parsing, bracketed paste; `keyReader` holds a split escape sequence until the next read or an idle timeout, and keeps everything up to the paste end marker as paste text), `term.ts` (raw mode and bracketed paste; no alternate screen)
- `src/commands.ts` — what the slash commands do, separate from how the TUI shows them; includes the project list logic: `orderProjects`/`orderedProjects` (pinned first, each group sorted by display-name label), `togglePin`, `liveAgents` (tmux windows minus the idle shell), and `deleteProject` (removes `projects/<id>` and its pin; refused while agent windows are live)
- `src/providers/` — `Provider` interface over an Anthropic-shaped transcript; `anthropic.ts` (SDK) and `openai.ts` (Codex subscription Responses, translated; preserves encrypted reasoning and tool IDs). `providerFor(model)`: `claude*` → anthropic, else openai
- `src/accounts.ts` — subscription accounts only: config `account` selects a Claude profile, `openaiAccount` selects a Codex profile; empty means `default`. API keys, old saved keys, developer-platform profiles and billing fallbacks are unsupported.
- `src/claude-auth.ts` / `src/codex-auth.ts` — provider-specific OAuth login, import and refresh. `src/oauth.ts` shares PKCE callbacks, private atomic writes and cross-process locks. State is under `auth/anthropic/` or `auth/openai/`. Tests use temporary homes and fake tokens, never native credentials.
- `src/view.ts` — renders and follows a transcript for the terminal
- `src/agent.ts` — the loop; all three roles are this with a different prompt and tool set
- `src/prompts.ts` — the three role system prompts: short behaviour lists, with the task-flow line and the complexity thresholds filled from config. `maxReviewRounds` (default 1; only an integer 0–100 is accepted, anything else falls back to the default; `loadConfig` also falls back to defaults, warning once on stderr, when config.toml does not parse) picks the task flow: 0 skips review (worker → reviewer with only "watch ci"); n ≥ 1 runs the loop below; if review n still finds problems, the worker gets one more pass with the notes, then the reviewer gets "watch ci" with no further review and the user hears what was left open. The orchestrator plans first (split as a table) and spawns nothing until the user says execute or dispatch. The cycle is orchestrator-driven: worker → reviewer (review mode: diff recon + `complexity`, no code changes) → worker again with notes, or reviewer again with "watch ci" (the only time it edits code; it pushes, opens the PR, runs `gh pr checks --watch`, fixes until green)
- `src/complexity.ts` — cyclomatic and Sonar cognitive complexity per function for JS/TS via `@babel/parser`; `src/tools/complexity.ts` is the reviewer's tool over it (changed files vs the default branch by default)
- `src/transcript.ts` — append-only JSONL with parent pointers
- `src/tools/` — `bash`, `spawn`, `message`, `ask` (orchestrator only), `complexity` (reviewer only); keep the set small
- `src/questions.ts` — the orchestrator's question queue for the user (`questions/`, a file per question, inbox-style names, status open/answered/skipped, atomic writes, an exclusive `<id>.closed` claim so a question closes once, rolled back to open if the write or inbox send fails; input cleaned and capped by `clean`/`cleanQuestions`). `ask` appends and returns ids at once, never blocking; `list`/`answer`/`skip` are the API for the TUI, and answering or skipping sends `[<id>] ...` to the orchestrator's inbox from `user`. A second answer or skip is refused
- `src/runner.ts` — worktree + tmux backend
- `src/inbox.ts` — one FIFO inbox per agent (`inbox/<agent>/`, a file per message); with the transcripts, the only state on disk. `message` sends to any address: `orchestrator`, `user`, or an agent id. Agents read their inbox before the first request, after each tool call (delivered with the tool results, never interrupting one), and after every turn, and keep going while messages arrive

Each agent gets its task from the first user message (spawn's brief or the inbox) and the tool descriptions, so keep those descriptions precise. The system prompt is the provider's Claude Code/Codex identity line followed by the role prompt from `src/prompts.ts`; keep those prompts short lists.

Rules:

- All state lives under `~/.parallels` (`src/config.ts` has the layout). A project's id is its folder name and never changes; the status line shows its display name (`displayName` in `src/commands.ts`). `PARALLELS_HOME` overrides it in tests.
- No task list. Everything is keyed by branch: `spawn(prompt, branch, role)` seeds `transcripts/<role>-<branch>.jsonl` and starts the agent in `worktrees/<branch>`.
- Agents only know their cwd. Never read the host or another worker's worktree.
- Tool results are byte-capped when appended to the transcript.
- Prefer `Bun.file`, `Bun.$`, and `bun:test` over npm packages.
