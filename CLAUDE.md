# parallels

A light-context agent harness: orchestrator → worker → reviewer loop, each agent in a tmux window. See PLAN.md for the design.

Bun + TypeScript. Use `bun` for everything (`bun test`, `bun run check`, `bun src/cli.ts`). No Node, npm or vite.

Layout:

- `src/cli.ts` — `start [project] [git-url]`, `msg`, `agent`, `agent-exit` (internal: the follow-up after a non-zero agent exit), `version` commands. `start` opens the inline TUI; run inside a git repo, it opens the `orch-xxxx` project cloned from that repo's origin, creating one if none exists (`repoHere` / `projectFor` in `src/commands.ts`), and Ctrl+N clones from it too
- `src/tui/` — the bare inline TUI, like Claude Code and Codex: no alternate screen; finished lines of the active page go once into the terminal's own scrollback (scroll with the terminal; no PgUp/PgDn), and only the live region at the bottom (the partial streaming line, a menu or the project list, the status line, the input area) is redrawn; switching pages, resizing, `/agents` and `/back` clear the screen and scrollback and reprint that page (or transcript); output for a page that is not active only goes into its history; quitting drops the live region and leaves the output with the cursor on a fresh line. Frames are throttled (one per 16ms at most) and a resize reprints once it has settled (120ms; nothing is drawn meanwhile); the live region shows "opening…" while the start pages open, and nothing is cleared at start; every page opens rebuilt from its orchestrator's transcript like `claude --continue` / `codex resume` (`restore.ts`), so the first page is printed under the shell's output and later ones on switching to them; ↑/↓ input history is per project (`history.ts`); console output (e.g. the config loader's warning) is routed into the scrollback while the TUI runs; a frame that throws is reported once and the app keeps going. `app.ts` (one page per orchestrator; a page's history (`Line[]`) keeps plain lines as they are and the orchestrator's markdown as written (streamed blocks, and replies led by their sender), laid out at the current width whenever drawn, so reprints after a resize fit tables again; only orchestrator text (the stream, replies, and, in the `/agents` view, every agent's assistant text — worker and reviewer too, as Claude Code renders subagent text — via `parts` in view.ts) is markdown, while user messages, commands, errors and tool lines (written with `plain` set by agent.ts) stay plain; Ctrl+N starts `orch-xxxx` at once, `/rename <name>` sets a display name only (saved in `projects/<id>/name`; the folder, id, tmux session and running agents are untouched, so it works mid-turn; names must be unique, printable, no bidi overrides; `/new <id>` and Ctrl+N's orch-xxxx never reuse another project's display name), Ctrl+Z / Ctrl+X switch, Ctrl+B or `/projects` (Ctrl+B is tmux's prefix) toggles a list of every project, drawn like the /models menu above the status line: ↑↓/jk, Enter opens and closes it, `p` pins (config `pinned`), `d` deletes after a plain y (Ctrl/Alt chords do nothing in the list), Esc closes; rows show each project's display name (`/rename`) while open, pin, delete and live checks use its id; `AppDeps.projects` stubs its tmux checks in tests; `/keys` echoes what the terminal sends; `/help` lists the commands: `/agents` picks a transcript to view live, `/back` leaves the agent view (listed only there), `/models [id]`, `/review-rounds [n]` (shows or saves `maxReviewRounds`; the orchestrator re-reads config every turn, so it applies from its next turn), `/accounts`, `/login claude [profile] | codex [profile]` (aliases: anthropic/openai), `/new [name] [git-url]`, `/close` closes the whole page, `/quit`. Every command works at any time: mid-turn, while viewing an agent (plain text there is refused until `/back`), and while signing in (a second `/login` is refused; plain text is held in the app and sent as soon as sign-in succeeds, or dropped with a note if it fails); a dimmed status line above the input shows the page's display name, remote and the number of open pages, led while a turn runs by a braille spinner "thinking…/working… Ns" (a live `/agents` view shows "following <agent>" instead, re-checked via tmux (`liveAgents`) about once a second, one call per project at a time), and "N busy" for busy background pages; a 100ms timer animates it only while something is busy — `AppDeps.clock` and `agents` are injectable for tests; the status text is built in app.ts, apart from the layout), `restore.ts` (pure, transcript entries → `Line[]` exactly as the page showed them live: the parent chain from the head back to the root or the latest summary (only the current branch; a summary leads with a dim "… earlier conversation summarized"); user messages as "> …" (`userLines`, also used by submit), agent messages as one dim "From <id>: <first line>…" (`reportLine`; live they come from the orchestrator's `report` hook, which sees each inbox message as it reaches the transcript, parsed back by `parseFormatted` in inbox.ts; within one inbox turn the user's lines go first, as they showed when sent), assistant text through a `MarkdownStream` cut exactly as the stream cuts it, tool calls as agent.ts's dim "▸" lines, tool results and thinking hidden, the orchestrator's `message` calls to the user that were sent shown as labelled replies (`replyLine`) after their turn; only the newest whole messages within `MAX_RESTORED_ROWS` (200) rendered rows at the current width, at least the newest one, led by a dim "… N earlier messages"), `history.ts` (input history: `projects/<id>/input-history`, one JSON string per line, newest last, `MAX_INPUT_HISTORY` (500) entries, blank lines and repeats of the last entry not saved, written whole via temp file + rename, one write at a time per page, never recreating a deleted project's folder; loaded on openPage), `markdown.ts` (pure, markdown → styled lines at a width, SGR and OSC 8 only: `takeBlocks` cuts the source into blocks (a line, a blank run, a fenced code block, a table) that each render alone (`renderBlock`), as a source line break stays a line break like Codex; headings bold (h1 underlined), `**`/`*`/`_`/`~~`/code spans (cyan), stricter than CommonMark so an opener never follows a letter or digit (snake_case, 2*3 stay literal); a closer skips escapes, code spans and nested spans (`*a **b** c*`); `-` bullets and numbers as written with hanging indents, nesting keeps the source indent; quotes behind a dim bar; code behind a dim gutter with the language as a label, cut only when wider than the screen; links (balanced parentheses allowed in the URL) as OSC 8 with the URL after in brackets when it differs from the text (Codex), empty text showing the URL, and only http(s)/mailto as OSC 8 (other schemes plain text); a table needs a delimiter row with as many cells as its header (GitHub); tables box-drawn with a bold header, the widest columns shrunk (`fitColumns`, at least 6 columns each) and their cells word-wrapped, else one "key: value" block per row (a header-only table lists its header cells); `wordWrap` carries styles and links across breaks; widths by Bun.stringWidth), `mdstream.ts` (`MarkdownStream`: `feed(chunk)` returns the blocks completed so far (a line at its newline, a code block at its closing fence, a table at the first non-row line, a possible table header at the next line), `pending` is the raw rest for the live region, `flush()` ends a reply; any chunking gives the same blocks as one feed), `render.ts` (pure, state → escape codes: `commit(lines, cols)` wraps finished lines for the scrollback; `live(frame, prev)` erases the previous live region (from the cursor's row up to its first row, then clear to the end of the screen), writes the partial line, a menu or the project list, the status line and the input area, which grows to a third of the screen and scrolls only when the cursor leaves it, and leaves the cursor in the input; `append` commits lines above it; `reprint` clears screen and scrollback and writes a page from scratch; the region always fits the screen; `sanitize` strips every escape but SGR and OSC 8 links, and every control but the tab, from committed and live text so stray tool output cannot move the cursor), `testing.ts` (`FakeScreen`, a faithful fake terminal for tests: visible screen plus scrollback, pending-wrap autowrap, wide characters, clamped cursor moves, and it throws on any escape or control it does not model or on a write that leaves synchronized output on or the cursor hidden), `editor.ts` (pure multi-line editing, independent of the frame: grapheme-aware insert/delete, word moves/deletes, wrap by display width → row/col, Up/Down between rows before history; Home/End and Ctrl+A/E/U/K act on the current line), `keys.ts` (legacy, xterm modifyOtherKeys and kitty key parsing, bracketed paste; `keyReader` holds a split escape sequence until the next read or an idle timeout, and keeps everything up to the paste end marker as paste text), `term.ts` (raw mode and bracketed paste; no alternate screen; while open, `exit`/SIGTERM/SIGHUP/uncaughtException handlers end synchronized output and paste mode, show the cursor, erase the live region (`eraseOnExit`, kept current by the app) and leave raw mode)
- `src/commands.ts` — what the slash commands do, separate from how the TUI shows them; includes the project list logic: `orderProjects`/`orderedProjects` (pinned first, each group sorted by display-name label), `togglePin`, `liveAgents` (tmux windows minus the idle shell), `exitWatchdog` (the TUI runs it for every open page on each inbox poll, via `App.watchPages`; tmux errors come back as null from `liveAgentsOrNull` so they never look like "all windows gone"; see `src/exits.ts`), and `deleteProject` (removes `projects/<id>` and its pin; refused while agent windows are live)
- `src/providers/` — `Provider` interface over an Anthropic-shaped transcript; `anthropic.ts` (SDK) and `openai.ts` (Codex subscription Responses, translated; preserves encrypted reasoning and tool IDs). `providerFor(model)`: `claude*` → anthropic, else openai
- `src/accounts.ts` — subscription accounts only: config `account` selects a Claude profile, `openaiAccount` selects a Codex profile; empty means `default`. API keys, old saved keys, developer-platform profiles and billing fallbacks are unsupported.
- `src/claude-auth.ts` / `src/codex-auth.ts` — provider-specific OAuth login, import and refresh. `src/oauth.ts` shares PKCE callbacks, private atomic writes and cross-process locks. State is under `auth/anthropic/` or `auth/openai/`. Tests use temporary homes and fake tokens, never native credentials.
- `src/view.ts` — renders and follows a transcript for the terminal
- `src/agent.ts` — the loop; all three roles are this with a different prompt and tool set
- `src/prompts.ts` — the three role system prompts: short behaviour lists, with the task-flow line and the complexity thresholds filled from config; on `[agent-exit]` the orchestrator tells the user and respawns the agent once, stopping if it exits the same way again. `maxReviewRounds` (default 1; only an integer 0–100 is accepted, anything else falls back to the default; `loadConfig` also falls back to defaults, warning once on stderr, when config.toml does not parse) picks the task flow: 0 skips review (worker → reviewer with only "watch ci"); n ≥ 1 runs the loop below; if review n still finds problems, the worker gets one more pass with the notes, then the reviewer gets "watch ci" with no further review and the user hears what was left open. The orchestrator plans first (split as a table) and spawns nothing until the user says execute or dispatch. The cycle is orchestrator-driven: worker → reviewer (review mode: diff recon + `complexity`, no code changes) → worker again with notes, or reviewer again with "watch ci" (the only time it edits code; it pushes, opens the PR, runs `gh pr checks --watch`, fixes until green)
- `src/complexity.ts` — cyclomatic and Sonar cognitive complexity per function for JS/TS via `@babel/parser`; `src/tools/complexity.ts` is the reviewer's tool over it (changed files vs the default branch by default)
- `src/transcript.ts` — append-only JSONL with parent pointers
- `src/tools/` — `bash`, `spawn`, `message`, `ask` (orchestrator only), `complexity` (reviewer only); keep the set small
- `src/questions.ts` — the orchestrator's question queue for the user (`questions/`, a file per question, inbox-style names, status open/answered/skipped, atomic writes, an exclusive `<id>.closed` claim so a question closes once, rolled back to open if the write or inbox send fails; input cleaned and capped by `clean`/`cleanQuestions`). `ask` appends and returns ids at once, never blocking; `list`/`answer`/`skip` are the API for the TUI, and answering or skipping sends `[<id>] ...` to the orchestrator's inbox from `user`. A second answer or skip is refused
- `src/runner.ts` — worktree + tmux backend. `agentCommand` returns an argv that tmux execs directly (`new-window … -- argv`), never through the user's default shell: workers and reviewers run a fixed `sh -c` script with every value passed as a positional parameter (nothing is quoted or spliced); after a non-zero exit other than 70 (`SETTLED_EXIT`: run already closed) it runs `parallels agent-exit` with the same run id. `tmux.windows` returns null when tmux could not be asked, [] when the session or server is gone
- `src/exits.ts` — `[agent-exit]` notices to the orchestrator's inbox, from the agent's id, when a worker or reviewer stops without reporting. Senders: `supervise` in the agent process ("crashed: <error>", then exit 70; "finished without reporting"; "killed by SIGHUP/SIGTERM/SIGINT" from the in-memory state, then exit 128+n), `afterExit` (the shell follow-up: "exited (code n) without reporting"), and the TUI `watchdog` ("'s window is gone" for an agent seen live on an earlier poll; on its first check per project, a sweep of every run on disk: "stopped while the TUI was not watching"). `runs/<id>.json` holds the current run: run id, pid, state, last step and tool. Report rule: only the final report counts. A successful `message` to "orchestrator" sets state `reported`; any later tool call or inbox message sets it back to `running`, so an interim "starting…" message does not silence a later notice. A run is closed by an exclusive create of `runs/<id>.<run>.exit`, by whoever sends its notice (or silently, when it ended on a report), so each run gets at most one notice; claims are pruned only after a day, so an old run's follow-up still sees its claim after a quick respawn. The watchdog skips a check when tmux could not be asked and only sends once the run's pid is dead (`process.kill(pid, 0)`). Notices carry role, branch, last step and tool, the error, and the uncommitted count, computed only when a notice is built: `git --no-optional-locks status --porcelain` with a 3s hard timeout (1s in a signal handler), "unknown" on timeout; the watchdog runs it in `worktrees/<slug(branch)>`
- `src/inbox.ts` — one FIFO inbox per agent (`inbox/<agent>/`, a file per message); with the transcripts, the only state on disk. `message` sends to any address: `orchestrator`, `user`, or an agent id. Agents read their inbox before the first request, after each tool call (delivered with the tool results, never interrupting one), and after every turn, and keep going while messages arrive

Each agent gets its task from the first user message (spawn's brief or the inbox) and the tool descriptions, so keep those descriptions precise. The system prompt is the provider's Claude Code/Codex identity line followed by the role prompt from `src/prompts.ts`; keep those prompts short lists. Agents' messages to the orchestrator are full reports with no length limit (the worker and reviewer prompts, the `message` description and spawn's `prompt` description say so); only the orchestrator's output to the user is concise.

Rules:

- All state lives under `~/.parallels` (`src/config.ts` has the layout). A project's id is its folder name and never changes; the status line shows its display name (`displayName` in `src/commands.ts`). `PARALLELS_HOME` overrides it in tests.
- No task list. Everything is keyed by branch: `spawn(prompt, branch, role)` seeds `transcripts/<role>-<branch>.jsonl` and starts the agent in `worktrees/<branch>`.
- Agents only know their cwd. Never read the host or another worker's worktree.
- Tool results are byte-capped when appended to the transcript.
- Prefer `Bun.file`, `Bun.$`, and `bun:test` over npm packages.
